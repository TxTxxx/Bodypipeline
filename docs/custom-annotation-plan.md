# BodyPipeline 自定义标注功能计划

状态：实施范围与验收依据；本功能在 `codex/custom-annotations` 分支开发，合并前以 PR 验证记录为准。

本文最初基于 main 调研；实施基线改为 server，其已有语言标注草稿和修订导出能力已复用。当前操作说明见 [自定义人工标注](manual-annotations.md)。  
日期：2026-10-27。  
参考项目：本地 `data_annotation/Gimme7` 的 Tags 配置、标注类型定义和动态表单设计。

## 1. 要解决的问题

BodyPipeline 已能采集、上传、转换和预览机器人演示数据，但人工标注尚未形成可长期保存、可配置和可导出的完整流程。

目前 Visualizer 中已有 TASK AUG、SUBTASK、PLAN、MEMORY、SPEECH、VQA 等语言标注界面，但 BodyPipeline 未启用其标注后端，修改只保存在浏览器当前会话中；无法把它作为正式的标注交付流程。同时，这套固定类型不能直接满足成功与失败、失败原因、操作对象、接触状态、人工介入等业务字段需求。

本次计划增加一套由配置驱动的人工标注功能，让使用者能够：

1. 定义需要标注的字段和选项，无需为每个字段修改代码。
2. 对整个 Episode、某段动作和某一帧进行标注。
3. 在 Server 上可靠保存，重新打开后继续编辑。
4. 按标签筛选数据，查看标注进度，导出可供训练端读取的标注包。
5. 在不同机器人、相机布局和数据格式之间复用同一套功能。

## 2. 参考项目中值得借鉴的部分

Gimme7 将两种需求分开处理：

| 机制 | 面向的需求 | 可借鉴的做法 |
| --- | --- | --- |
| Tags | 成功/失败、左右手、操作工具等简单分类 | 配置分组、显示名称、存储值、快捷键，页面自动生成选项按钮 |
| Types | 一个事件或状态包含多个字段 | 保存类型定义，按字符串、数值、布尔值等类型生成表单 |
| 标注实例 | 用户在具体时间填写的数据 | 类型定义与标注值分离，实例引用定义并保存字段字典 |
| 保存与重开 | 标注可交付、可继续编辑 | 将标注实际保存至服务端，并保留关联数据和时间信息 |

借鉴的是配置驱动的交互和数据组织方式。BodyPipeline 的正式数据格式是 LeRobot v2.1 / v3.0，不需要为了采用这些功能改用 RRD。

参考项目也有尚未完整接通的部分：当前主界面未挂载通用动态填写表单，stream/ai 来源没有在通用提交流程中完整自动执行，子任务只消费第一个结果标签组。BodyPipeline 应按下面的验收要求完成端到端流程，不以“已有配置编辑器”作为交付完成标准。

## 3. 使用者看到的功能

### 3.1 标注方案管理

Server 工作台增加“标注方案”管理入口。一个方案可以包含多组快捷标签和多个结构化标注类型，例如：

```text
桌面操作标注方案
├── Episode 标签：任务结果、失败原因、难度
├── 子任务标注：步骤名称、操作对象、步骤结果
├── 时间区间标注：接触状态、人工介入
└── 单帧事件：抓取完成、物体滑落、异常备注
```

支持创建、复制、编辑、停用方案，并提供示例方案供复制使用。新数据集不自动套用示例标签。

用户选择数据集后，显式应用一个方案。相同方案可复用到不同数据集，也可以复制后调整。首期每个数据集使用一个方案版本，避免多个方案的字段冲突。

界面使用“任务结果”“操作对象”等业务名称；字段标识、版本等配置细节集中在方案编辑页面，不占据日常标注流程。

### 3.2 自定义字段

每个字段可配置：

| 项目 | 功能 |
| --- | --- |
| 字段标识 | 稳定的存储名称，如 `success`、`failure_reason` |
| 显示名称与说明 | 标注人员看到的名称、填写提示 |
| 数据类型 | 文本、整数、小数、布尔值、单选、多选 |
| 展示方式 | 输入框、多行文本、数字框、滑块、开关、选项按钮、下拉框 |
| 选项 | 显示名称与实际存储值分离，可调整选项显示顺序 |
| 约束 | 必填、文本长度、数值范围、步长、单位 |
| 默认值 | 可选；必须符合字段类型和约束 |
| 快捷键 | 可选；同一操作上下文内检查冲突 |

首期实现上述常用类型，不提供任意嵌套对象、任意脚本字段和复杂条件表单。字段控件与数据类型应有明确兼容关系，不能配置出“布尔值滑块”等无效组合。

任务结果默认应为“未标注”，不自动将未检查的数据标为成功。默认值不应自动代表“已完成标注”。

### 3.3 三种标注范围

| 范围 | 操作方式 | 示例 |
| --- | --- | --- |
| 整个 Episode | 在侧栏或顶部填写一次 | 本段是否成功、失败原因、场景、难度 |
| 时间区间 | 在视频时间轴上选择起止位置后填写 | 当前子任务、接触状态、人工介入、抓持状态 |
| 单帧事件 | 暂停到目标帧，点击添加 | 抓取完成、滑落、碰撞、关键帧备注 |

同一种范围允许多个标签组或标注类型，不能仅支持一个固定的“结果”字段。

时间区间可以编辑起止位置、移动、删除。首期不要求自动传播逐帧标注。单帧事件保存时必须吸附到数据中的实际帧。

不同类型可以重叠，例如“擦拭”区间内同时存在“人工介入”。类型可配置是否允许自身区间重叠；首期默认为允许，对互斥的步骤切分启用禁止重叠并给出明确提示。

### 3.4 在现有预览中完成标注

标注操作继续使用现有视频、相机切换和时间轴，不另建一套与预览脱节的视频播放器。

建议页面布局：

- Episode 列表：显示未开始、草稿、已完成状态，支持按标签和进度筛选。
- 视频区域：继续使用现有多相机预览与联动能力。
- 标注时间轴：按类型显示区间和事件，可隐藏不关注的轨道。
- Episode 属性区：显示整段任务标签与字段。
- 标注编辑区：选择条目后显示相应动态表单。
- 操作区：保存草稿、标记完成、上一段、下一段。

新增条目、编辑条目、删除条目均应给出可见反馈。提供保存前的本地撤销；切换 Episode 时，未保存修改必须有保护，不能静默丢失。

### 3.5 保存与完成状态

服务端持久化是首期必要能力，浏览器缓存只用于恢复未提交草稿。

首期支持三个状态：

1. 未开始：尚未进行人工标注。
2. 草稿：允许字段暂时不完整，但已填写的值仍需满足类型和范围约束。
3. 已完成：提交前检查必填字段、区间边界、选项是否合法等要求。

编辑已完成的数据后，重新进入草稿状态。页面明确区分“有未保存修改”“草稿已保存”和“标注已完成”，保存失败不能显示为成功。

沿用现有登录机制。当前共享管理凭据不能可靠区分真实操作者，因此首期记录更新时间、版本与操作来源，不宣称已经具备个人责任审计和多人审批能力。

## 4. 一个完整使用示例

以“拿海绵擦台面并归位”为例：

1. 负责人新建“桌面清洁”标注方案。
2. 添加 Episode 单选字段“任务结果”，选项为成功、失败。
3. 添加 Episode 单选字段“失败原因”，选项为抓空、滑落、擦拭不充分、其他；该字段首期可不设为必填。
4. 添加“子任务”区间类型，包含步骤名称、操作对象、步骤结果三个字段。
5. 添加“异常事件”单帧类型，包含异常类别与备注。
6. 将方案应用到一个转换完成或导入的 LeRobot 数据集。
7. 标注人员依次切分“拿海绵”“擦台面”“海绵归位”，填写字段。
8. 如果中途海绵滑落，在对应帧新增异常事件。
9. 保存草稿；确认完整后将该 Episode 标记为已完成。
10. 负责人筛选已完成且成功的 Episodes，导出标注快照，交给训练端处理。

该流程应能完全通过页面完成，不要求标注人员编辑 JSON 文件。

## 5. 现有语言标注如何处理

保留 TASK AUG、SUBTASK、PLAN、MEMORY、SPEECH、VQA 的语义，避免把同一个名字改成含义不同的业务字段。

首期处理原则：

- 将现有文字类标注接入服务端保存路径，复用通用保存、版本和冲突处理能力。
- 对 TASK AUG 提供 Episode 级任务改写入口；原始转换 instruction 作为来源信息保留，人工改写另存，不直接覆盖转换元数据。
- SUBTASK 沿用“步骤开始点到下一步骤开始点”的旧语义时，读取层需明确转换为区间；新建结构化子任务支持显式起止位置。
- PLAN、MEMORY 保留产生时刻，SPEECH、用户插话、VQA 保留事件时间与角色等信息，不将全部内容压成无类型字符串。
- 已有数据中的语言标注可以读取；首次人工修改作为新标注版本保存，不静默改写原数据列。
- 保留已有 VQA 框和关键点能力，首期不增加通用三维编辑器或掩码编辑器。

当前浏览器会话中的旧草稿可提供一次性“导入为服务端草稿”入口：用户先预览数量与内容，导入后完成校验。浏览器会话已丢失的内容无法恢复。

这些字段能否用于训练，由训练数据读取器和导出约定决定。首期不承诺填写后自动成为 prompt，也不宣称已支持 LeRobot v3.1 数据集导出。

## 6. 数据保存、版本和关联要求

### 6.1 定义与实例分离

建议按三类对象组织：

| 对象 | 主要内容 |
| --- | --- |
| 标注方案版本 | 字段定义、类型、选项、约束、显示配置 |
| 数据集绑定 | 数据集身份、采用的方案版本、数据版本、Episode 身份映射 |
| 标注记录 | 所属 Episode、类型、时间范围、字段值、修改版本与时间 |

标注记录引用确定的方案版本。修改显示名称可以发布新版本；已使用字段更改类型、移除选项或改变含义时，不得自动重新解释旧标注。已有字段和方案优先停用，历史快照继续可读。

首期不要求复杂自动迁移。数据集升级方案版本时，展示影响并显式执行迁移；无法迁移的值保留原版本，不能悄悄删除。

### 6.2 独立保存，保护原始数据

人工标注保存到 Server 管理的独立目录，沿用现有文件和 JSON 存储方式，不强制引入数据库。

- 模板和检索状态放入服务状态目录；实际标注产物放入可备份的数据存储目录。
- 不修改原始采集 HDF5、Manifest、机器人状态和动作数值。
- 不原地覆盖导入的外部数据集。
- 保存采用原子替换，并携带记录 revision；并发修改同一记录时提示冲突，不能以最后一次提交静默覆盖。
- 新预览链接、浏览器重开、Server 重启后，应读到同一份已保存标注。
- 标注服务不可用时，预览仍可读；界面明确提示无法完成服务端保存。

目录结构与 API 命名由实现负责人结合当前 Store、存储路由和部署布局确定；不要把永久标注身份绑定到临时预览链接。

### 6.3 Episode 身份与数据变化

Episode 索引可能因永久清理而重排，因此不能只以 `episode_index` 作为标注身份。

首期必须做到：

1. 为数据集和 Episode 建立持久身份；展示索引与持久身份分离。
2. 保存当前数据版本与索引映射；有来源血缘时关联原始 upload / capture 信息。
3. 相同数据集通过不同预览入口打开时共享标注；重新转换产生的新数据版本不自动继承旧标注。
4. 软删除进入回收站后保留标注，恢复后重新显示；默认导出排除回收站数据。
5. 永久清理使用现有旧索引到新索引映射同步更新关联，归档被清理 Episode 的标注。
6. 数据与标注映射发布须可恢复，不能出现数据已经重排、标注还挂在旧编号上的窗口；映射更新失败时不得发布未完成关联的数据版本。
7. 外部数据被修改且无法确认对应关系时，停止对旧标注的正常编辑和导出，提示重新确认关联，不按相同编号猜测匹配。

### 6.4 时间和相机

以数据集中实际帧索引和时间戳为准，不能只用 `秒 × FPS` 推算。区间存储统一采用起点包含、终点不包含的边界规则；界面可以显示为直观的起止帧，但需要一致转换。

相机相关标注引用元数据中的相机标识，不固定相机数量、名称或排列。跨转换结果迁移时间标注需要显式对齐映射，不直接复制浮点时间值。

## 7. 筛选和导出

### 7.1 首期筛选能力

- 按未开始、草稿、已完成筛选。
- 按 Episode 标签的单选、多选、布尔值筛选。
- 按是否包含指定区间类型或事件类型筛选。
- 展示筛选结果数量与标注完成进度；“已完成”不等于任务成功。

首期不提供复杂查询语言、跨数据集聚合报表和训练集自动优化。

### 7.2 首期导出标注包

提供独立标注包下载，至少包含：

- 固定版本的方案定义。
- Episode 属性、区间标注和单帧事件的 JSON / JSONL 数据。
- 数据集身份、数据版本、Episode 持久身份与当前索引映射。
- 关联源数据的元信息、校验依据、实际帧时间信息或明确的帧引用。
- 导出时间、筛选条件、包含的标注 revision 和完成状态。
- 字段、时间范围与未知值的解释说明。

导出读取一个一致的快照，不能混入导出过程中刚修改的一半数据。默认仅导出已完成且未进入回收站的数据，也允许显式导出草稿并在结果中标明状态。

标注包不包含视频等完整源数据；导出时明确提示需配套哪个源数据版本，避免被误认为独立可训练的数据集。需要可移交的完整数据时，在后续阶段提供“源数据副本 + 标注包”。

### 7.3 后续训练导出

后续按目标训练框架增加独立导出适配器，选择将字段用于指令、动作条件、监督目标、筛选或评估。

不能将 Episode 最终结果、未来的 memory、后续步骤答案等直接当作较早帧的推理输入。导出映射应区分“当时可获得的信息”和“事后标注的结果”，并记录转换规则。

需要写入 LeRobot 数据列时，生成新的导出目录、同步更新元数据并验证；不直接覆盖当前转换结果。是否升级语言 schema 或工具链另行评估。

## 8. 与现有系统的职责划分

- Client 继续负责采集与上传，首期不增加机器人端人工标注流程。
- Server 负责方案、持久化、校验、筛选、导出和血缘关联。
- Viewer 负责视频、时间轴和动态标注交互，通过受控接口保存。
- Doctor 和 Argus 结论继续独立存在，人工标注不自动覆盖质检结论或改变转换任务状态。
- Argus 未来可以生成待确认的候选标注，但候选、人工确认和完成状态需要明确区分。
- 登录、路径白名单和写操作保护沿用现有边界；浏览器提交受管数据集标识，不任意指定服务端写入路径。
- 通用页面和 API 不增加机器人型号分支；机器人差异通过现有元数据、Profile 与底层适配器表达。字段配置不承担机器人控制或执行能力。

建议由 BodyPipeline Server 提供标注接口，并通过 Viewer 网关提供同源访问。不要直接开放上游允许任意本地路径写入的标注后端。上游 Visualizer 的改动继续通过固定版本补丁或独立组件管理，并纳入构建指纹。

## 9. 分阶段交付

| 阶段 | 交付范围 | 完成标准 |
| --- | --- | --- |
| P0-1：保存基础 | 数据集与 Episode 身份、方案模型、版本、标注存储、语言标注保存、冲突处理 | 页面保存的标注在新会话和服务重启后可读，原数据不变 |
| P0-2：配置与编辑 | 方案编辑器、常用字段类型、三个作用范围、动态表单、时间轴编辑、完成状态 | 上述桌面清洁示例可全程通过界面完成 |
| P0-3：可交付闭环 | 筛选、标注包导出、回收站映射与恢复、文档 | 导出包可按身份与帧准确关联源数据，永久清理后关联仍正确 |
| P1：提高效率 | 批量标注与批量改值、模板共享、可移交完整数据包、明确目标的训练导出适配器 | 在真实数据集上验证节省人工操作且导出可被目标读取器消费 |
| P2：辅助标注 | Argus 候选标注、指定数据流取值、更多空间标注、复核流程 | 分别验证自动结果、人工确认、权限和版本追踪 |

P0 三部分共同构成首期可用版本；只交付编辑器或只交付浏览器保存不算完成。预估工期由负责人根据 Viewer 改造和真实数据回归成本给出，本提案不预设人天。

## 10. 首期验收清单

- [ ] 可在界面创建方案，配置文本、整数、小数、布尔、单选、多选字段及相应约束。
- [ ] 可配置多个 Episode 标签组和多个区间/事件类型，不需要修改源代码。
- [ ] 同一方案可应用于多个数据集，并固定各自使用的方案版本。
- [ ] 三种范围都能创建、编辑、删除；时间吸附、区间边界、相机关联正确。
- [ ] 字段配置和提交值均有服务端校验；未知字段、错误类型、非法选项明确报错。
- [ ] 必填检查在标记完成时生效，草稿可留空；未标注不会自动记为成功。
- [ ] 服务器保存、新标签页重开、服务重启后的读写结果一致，保存失败反馈准确。
- [ ] 两个窗口修改同一记录会收到冲突提示，不静默覆盖。
- [ ] 已有语言标注可读写，旧浏览器草稿可显式导入，原始 instruction 和源数据不被覆盖。
- [ ] 方案升级不破坏历史值，停用字段后历史快照仍可解释。
- [ ] 软删除、恢复、永久清理与中断恢复后，标注不会错挂到其他 Episode。
- [ ] 数据源发生外部变化时能识别并阻止错误关联和导出。
- [ ] 筛选及导出快照一致，回收站、草稿、未知值的处理符合页面说明。
- [ ] 至少覆盖两组不同相机布局、关节维度和元数据组织的样本，验证通用层无型号特例。
- [ ] 使用一个真实数据集完成“配置 → 标注 → 保存 → 重开 → 筛选 → 导出 → 重新关联源帧”的人工验收。
- [ ] 保持现有采集、转换、预览、Doctor、Argus 与回收站功能可用。

验证应包含字段与时间校验测试、API 持久化与冲突测试、回收站关联恢复测试，以及浏览器完整操作验收。不同机器人样本通过软件契约验证，不代表新增机器人已经完成真机适配。
