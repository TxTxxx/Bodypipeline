## 1. 系统定位与本轮范围

系统负责生成、检查、人工修改和导出标注，优先做好与视频帧对齐的子任务身份、执行次数和时间边界。评分及详细内容分析作为辅助能力。

标签如何成为训练类别、如何参与训练、是否作为背景类及采用何种训练策略，由下游使用者决定。本系统负责准确表达和导出结果，不代替训练端做这些选择，也不按训练用途增加导出限制。

第一版沿用 Server 已登记、可读取的 LeRobot 数据集输入，原始视频、HDF5 等继续经过已有转换流程。暂不处理双臂并行，不在本轮新增并行轨道或相关导出能力。

## 2. 自由分析与模板标注分为两种模式

| 模式 | 约定 |
| --- | --- |
| 自由分析 | 沿用 Argus 的原生分析能力，允许自由描述录像内容。 |
| 模板标注 | 使用专门的提示词和业务输出结构，围绕指定模板生成子任务标注。 |

模板模式复用 Argus 的数据准备、抽帧、模型调用、费用记录和续跑能力。其主要业务结果遵循一套模板标注契约，不再要求同一次模型回复同时生成另一套完整的原生业务时间线。需要保留的原生观察信息应明确其辅助用途。

自由分析是否用于下游训练，由使用者决定；不强制要求自由分析结果先映射到模板才能导出。

## 3. 模板定义与切分单位

每个模板子任务应支持以下信息：

- 稳定的 ID 与名称。
- 业务定义。
- 包含和排除的动作。
- 可根据画面或传感器证据判断的开始条件、结束条件。

模板模式只允许使用模板中的 Subtask ID，不允许模型自行新增或改名。保留模板快照、摘要和服务端校验，不能在校验失败后静默回退到自由命名。

基本标注单位是一次子任务的执行尝试（attempt）。一个子任务可以按模板定义涵盖接近、调整、抓取等多个细动作，不要求每个细动作都拆成子任务。

失败后重新执行应记录为另一次尝试，包括相邻同名的尝试。录像事实优先：不为凑齐模板而补造未发生的步骤，不把失败标成完成，也不将未知活动强行归入某个合法标签。

## 4. 时间边界与精度

- 默认目标为相对人工参考边界误差不超过 ±0.2 秒，允许配置调整。
- 先识别子任务和大致区间，再在候选交界附近加密取证、细化边界。
- 证据不足的边界明确标记待复核，不通过增加小数位数制造精确的表象。
- 边界细化产生的模型调用纳入任务总预算。

±0.2 秒是待实际试跑验证的质量目标，不代表当前实现已经达到。系统不以模型自报的高置信度代替人工确认。

## 5. NULL、未知和模板未覆盖

| 状态 | 含义 |
| --- | --- |
| `NULL` | 已观察并确认的背景或无任务区间。 |
| `UNKNOWN` | 遮挡、证据不足等原因导致无法判断。 |
| `OUT_OF_TEMPLATE` | 明确存在活动，但模板没有对应标签。 |

三者应分别记录、显示并在导出中保留区别，不通过新增 Subtask 名称表达这些状态。对其训练用途不设置系统默认策略。

静止只是运动状态，不自动等于 NULL。任务中的持物、支撑、等待及短暂停顿，应根据子任务定义和起止条件判断是否仍属于当前 attempt。

## 6. 试跑与全量运行

用户可以任选以下入口：

1. 选择 1–5 条 Episode 进行试跑，检查效果、调整配置后，再决定是否运行全量。
2. 直接运行全量。

试跑是可选能力，不能成为强制前置步骤。试跑结束后，由人明确决定是否继续，不自动启动全量。

同配置下已成功的试跑结果可以复用。参数变化后是否重算、重算哪些结果，由人选择。不要求建立固定的 20 条人工验收集，也不以该固定数量作为运行门槛。

## 7. 人工审核与导出

AI 生成的结果首先是待审核草稿。编辑保存与审核确认是两个不同动作，以 Episode 为单位记录确认状态。

支持人工选择多个正常 Episode 批量确认；有未处理风险的 Episode 应单独检查。批量操作前展示范围、异常和未标注区间，后端检查确认条件。

确认状态绑定具体标注内容。确认后修改内容，应重新进入待审状态，并保留确认过的内容供追溯；这不等于强制新建一个用户可见的标注版本。

未审核草稿也允许导出。由用户决定导出范围，输出应保留审核状态、异常区间及模板信息，不将草稿伪装为已确认结果。

## 8. 自定义字段与评分

保留自定义字段和评分能力，创建字段时可配置含义说明及评分尺度。

缺少证据或明确评分标准时，允许 AI 留空，由人补填。缺值不影响其他已经有效的子任务切分结果，不要求模型为填满字段而编造评分或事实。

## 9. 参数、重跑与标注版本

修改模型、模板、采样等参数，不自动强制生成新的用户可见标注版本。是否替换当前标注、另存版本或重算，以及采用哪份结果，均由用户决定。

已有人工修订或确认的结果不能被重跑静默覆盖。替换必须基于用户的明确选择。

系统仍需保存每次执行的实际参数、模板快照及必要运行记录，用于结果追溯。执行记录与用户管理的标注版本是不同概念。

## 10. 自动重试与预算

以单个逻辑模型请求为单位：首次请求之外，最多自动重试 3 次，即该请求最多包含首次及 3 次重试。网络暂时故障、模型回复格式错误和模板校验失败统一受此上限约束。

- Server 与 Argus 的各层共享重试计数，避免多层重试次数叠加。
- 凭据、配置等明确无法依靠重试解决的错误直接报错。
- 重试针对失败请求，已成功结果保留。
- 重试、边界细化和其他标注调用均受任务总预算限制；费用及未结算预留纳入预算。
- 达到预算或重试上限时，保留有效结果并明确标出未解决部分，供人工处理或按现有续跑机制继续。

## 11. 审核证据与可追溯性

审核界面应能查看边界前后画面、对应模板判据和简短证据依据，帮助人工判断子任务和边界是否正确。

保留实际发送的提示词、模型参数及采样帧时间或索引，不能将模型输出的任务摘要当作实际请求提示词。结果应能追溯到对应来源数据与模板快照。
