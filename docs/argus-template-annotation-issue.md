# Argus 与任务模板的标注规则及切分问题

- 记录日期：2026-11-14。
- 状态：已完成静态代码核查，实际失败样本与根因待验证；尚未实施修复。
- 核查范围：本地 `origin/server`，提交 `49aff8e3912610c78bc9f549faa07c268d87dd9d`。
- 该分支固定的 Argus 版本：`383ca11cf260e2db6da7ba901b8d60cfa8fc68fb`。

## 1. 问题现象与结论边界

用户反馈自动标注存在以下问题：

1. 子任务切分及起止时间不准确。
2. 标注偏离提供的 prompt，会自行命名子任务。

代码表明，模板模式在保留 Argus 原生提示词及输出的同时，追加一套固定任务模板约束。因此存在命名、粒度和并行策略不一致的风险。但两套结果属于不同字段，可以同时成立，不能仅凭这项设计认定它们必然冲突，也不能据此认定已找到上述实际样本的根因。

本记录依据源码核查，尚未检查用户失败任务的原始模型回复、实际模板快照及部署版本，也未进行真实模型调用。

## 2. 分支与功能范围

`server` 分支已经有共享任务模板、AI 初稿、标注预览、人工修改和导出功能。模板接入始于提交 [de1f7a2：绑定 AI 草稿与共享任务模板](https://github.com/implllly/Bodypipeline/commit/de1f7a249b7959d16a9485a60310109a923bac32)。

记录时当前工作区检出的是 `main`，提交 `00670a620e1f5a3d94a41576a3cac832b3a31bff`。该工作树没有这套模板模块，不能用其内容分析实现概括 `server` 分支的自动标注功能。下文涉及的源码路径均指上述固定的 Server 提交，不代表已确认线上部署正在运行该版本。

## 3. 当前实现

```text
创建并保存共享任务模板
    ↓
自动标注页面选择模板（也可选择“自由分析”）
    ↓
Server 冻结模板快照、模板库版本和摘要
    ↓
Argus 原生标注规则 + BodyPipeline 模板约束 + 当前录制资料与画面
    ↓ 同一次模型回复
Argus 原生结果 + bodypipeline_task
    ↓
模板校验、恢复原视频帧位置
    ↓
task_document → 模板预览、人工审核及导出
```

已核实的实现细节：

- [模板补丁](https://github.com/implllly/Bodypipeline/blob/49aff8e3912610c78bc9f549faa07c268d87dd9d/patches/argus/0002-task-template.py) 使用 `fixed += task_contract(ctx)`，在原有公共提示词后追加模板约束。
- [模板合同](https://github.com/implllly/Bodypipeline/blob/49aff8e3912610c78bc9f549faa07c268d87dd9d/pipeline/server/argus_template_contract.py) 要求在正常 Argus JSON 之外，同时返回 `bodypipeline_task`，包含固定子任务 ID、执行尝试、NULL 区间及自定义字段。
- [结果校验](https://github.com/implllly/Bodypipeline/blob/49aff8e3912610c78bc9f549faa07c268d87dd9d/pipeline/server/template_annotation.py) 拒绝未知 Subtask ID、错误模板摘要、非法字段和无效时间区间；模板结果不合格时标记失败，不静默回退到自由描述，也不自动扩充模板。
- [结果读取](https://github.com/implllly/Bodypipeline/blob/49aff8e3912610c78bc9f549faa07c268d87dd9d/pipeline/server/argus_annotation.py) 和[导出](https://github.com/implllly/Bodypipeline/blob/49aff8e3912610c78bc9f549faa07c268d87dd9d/pipeline/server/subtask_export.py) 已有模板结果处理路径。当前没有证据表明它们直接混用了两份动作标签。

## 4. 潜在不一致与约束缺口

### 4.1 同一次请求需要兼顾两套标注目标

| 维度 | Argus 原生标注 | BodyPipeline 模板标注 | 待明确之处 |
| --- | --- | --- | --- |
| 命名 | 动作允许自由描述 | 只能使用模板 Subtask ID，显示名称由模板确定 | 原生动作如何对应模板子任务 |
| 粒度 | 接近、抓取、搬运、放置等动作阶段 | 一个模板子任务的一次执行尝试 | 哪些细动作应归入同一次尝试 |
| 并行 | 可分别描述左右臂动作，时间段可能并行 | 同一帧只能归属一个 Subtask | 双臂同时执行不同子任务时如何表达 |

Argus 的原生规则见[固定版本提示词](https://github.com/Pantheon-Industries-Inc/argus/blob/383ca11cf260e2db6da7ba901b8d60cfa8fc68fb/label/prompts.py)。

例如，模板中的“抓取杯子”可能希望涵盖接近、调整夹爪和提起；Argus 原生时间线会把这些动作分别描述。两者可以并存，但当前模板合同没有明确提供这些动作与业务子任务的映射、合并及边界规则。判断这会增加模型混淆风险，仍需通过失败样本和对照实验验证。

### 4.2 模板缺少专门的切分判据

[当前模板结构](https://github.com/implllly/Bodypipeline/blob/49aff8e3912610c78bc9f549faa07c268d87dd9d/pipeline/server/task_annotations.py) 中，`Subtask` 只有 `id` 和 `name`。尚无专门字段定义：

- 子任务的业务含义及包含、排除的动作。
- 可从画面或传感器判断的开始、结束条件。
- 允许的前后关系、重复执行及失败重试规则。
- 并行子任务的表示方式。

仅靠名称，模型仍需要自行推断粒度和边界。是否需要覆盖整个视频、如何处理未观察到的区间，也应与任务要求明确对齐；当前合同区分了明确背景的 NULL 与未标注区间，不能将两者混为一类。

### 4.3 格式校验不等于语义正确

现有校验能约束固定 ID、字段类型及选项、评分范围、时间范围和区间不重叠，但不能证明：

- 某个合法子任务 ID 对应的动作真的发生了。
- 一次尝试的开始、结束帧正确。
- 模型没有漏掉、错误合并或过度拆分某次尝试。

因此，“标签名称合法但边界错误”的结果仍可能通过校验。新增名称若只出现在 Argus 原始时间线中，也不能直接判定模板词表已被污染，应先确认查看的是哪一层结果。

## 5. 后续排查与复现

1. 确认实际 Server 提交及安装的 Argus 版本、模板补丁状态。
2. 选择一条失败任务，检查任务记录中的 `task_template`、`template_signature`、`template_library_revision` 和工作目录中的 `task-template.json`，确认使用了预期模板，而非自由分析。
3. 对照原始视频、原始模型回复中的 `labels.bodypipeline_task`、Argus 原生时间线及最终 `task_document`，定位名称或边界变化发生在哪一层。
4. 检查任务实际保存的模型、采样率、输出上限、任务说明，以及截断、解析或模板校验错误。以实际参数和请求证据为准，不直接套用其他分支的默认值。
5. 由人工为同一视频提供目标子任务与边界，明确允许的误差及重试、并行处理方式，再比较当前提示词与统一模板规则后的结果。

本节是待执行步骤；当前尚无样本级复现结论或质量对照数据。

## 6. 建议改进方向

以下是待评估方案，不代表已经实施或证明有效：

1. 模板模式采用明确的业务标注契约；需要保留原生动作描述时，说明其辅助用途及与模板结果的关系，避免让两套粒度相互替代。
2. 为子任务补充定义、起止判据、粒度和异常规则，并明确任务是否允许并行；公共契约应能表达不同机器人所需的能力。
3. 对时间精度要求高的场景，评估先粗定位、再在交界处加密取证和细化边界的流程，并记录新增调用成本。
4. 保留现有模板快照、固定 ID 校验、失败不回退、费用凭据及续跑机制。调整提示词或输出结构时，同时核对 Argus 的解析、结果完整性和请求身份校验，不能只删除原生输出字段。
5. 在页面与导出中清楚标识模板业务结果和原生观察结果，保留人工审核与修订能力。

## 7. 验收要点

- 模板结果只使用冻结快照中的 Subtask ID；未知 ID 明确失败，不自动改名或扩充词表。
- 在人工复核样本上评估边界误差、漏标和过度切分，不能只看 JSON 或类型校验是否通过。
- 明确覆盖双臂并行、相邻同名重试、背景、未观察区间及长视频系统分段的行为。
- 模板结果从模型回复到预览、审核、导出保持一致，且可追溯模板快照与原始证据。
- 保留现有预算、取消、续跑和已完成结果复用行为；额外模型调用需要纳入成本核算。
