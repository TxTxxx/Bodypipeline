# 操作方式与动作语义

用于确定新机器人或新操作方式需要记录什么，以及如何验证数据映射。以下是核查清单与设计选择，不是已实现的字段 schema，也不规定所有任务必须采集全部流。

## 分开描述硬件、操作方式和采集协议

| 维度 | 应记录的事实 |
|---|---|
| 机器人硬件 | 型号、传感器、执行器、实际自由度和夹爪含义 |
| 操作方式 | 主从臂、VR 手柄/手势、普通手柄、动捕、拖动示教，或用户要求的自动/混合控制 |
| 控制接口 | 控制器接收的位置、速度、力矩、末端目标或其他命令；由实际接口确认 |
| 采集接口 | recorder 的 ROS2 Service、HTTP、SDK 或文件输出机制 |
| 原始格式 | 目录/文件契约和版本；不要从机器人型号推断 |
| 数据用途 | 消费端预期的 observation/action、辅助输入及事件含义 |

VR 属于输入方式，ROS2 属于通信与软件接口，二者不是互斥的 capture mode。当前 `mode=ros2` 可以承载经适配的 VR recorder；把 mode 改成 `vr` 并不会自动获得支持。人通过 VR 遥操作时可仍使用 `control_mode=teleoperation`，但要有能区分动作语义的 Profile 和版本。

## 选择 action 的采样位置

画出实际链路，并把文件或 topic 对应到具体节点：

```text
操作者/策略输入 → 映射、标定、重定向等处理 → 控制器命令 → 执行器与观测
```

逐项核查：

- 数据集的 action 代表哪个边界、给哪个消费端使用；选择与未来输出/执行接口一致的表示，并记录选择依据。
- 命令取自映射、滤波、限幅或 IK 前还是后；如果控制器内部目标不可见，不将入口命令宣称为实际执行命令。
- state 是测量值、估计值还是目标值；相同维度不表示语义相同。不能用实测轨迹冒充缺失的命令。
- 若任务明确预测 VR 输入本身，可以将输入定义为 action，但必须记录消费端的后续映射，不能同时宣称其已是机器人控制命令。
- 保留判断所需的原始输入、命令或事件；对没有命令流的拖动示教，说明能生成观测轨迹还是有依据的动作标签，不静默补零或用下一帧状态替代 action。

同一机器人更换输入方式时，若命令边界、动作表示和数据契约完全一致，可复用格式处理器；变更的映射/标定或语义需版本化，并按实际差异更新 Profile 与血缘。

## VR、位姿和手势输入

依据目标设备文档、控制代码、标定文件及样本核实以下项目，不套用某个 SDK 的默认值：

| 项目 | 核查与验证 |
|---|---|
| 坐标关系 | 各流坐标系、轴方向/手性、长度与角度单位、变换方向及标定版本；用已知姿态或位移样本验证 |
| 姿态表示 | 四元数分量顺序、归一化要求，或欧拉角顺序/约定；与实际控制接口匹配 |
| 动作定义 | 绝对目标还是增量、参考姿态、增量应用坐标系、重置/recenter 后参考变化 |
| 左右与重定向 | 手柄/手到哪条臂的映射、缩放、IK/滤波/限幅所在位置及版本 |
| 离合与夹爪 | clutch/deadman、抓取按钮、模拟扳机、夹爪值的单位/开闭方向/状态机 |
| 有效性 | tracking validity、断连、陈旧帧、恢复和丢样处理；缓存位姿不能被无条件视为新输入 |
| 录制事件 | 暂停、参考重置、控制权切换是否切分 episode、标记片段或生成有效性掩码；按消费端要求决定 |

录制服务负责保存这些信息和显示必要诊断；不因适配数据就自动实现或修改 VR 运动映射。需要新增映射时，由明确需求、接口定义和样本测试约束。

## 自动或混合控制（仅在任务需要时）

分别记录策略提议、人工输入、仲裁后命令中实际可获得的流，标明最终 action 来源；不能把未被执行的策略提议当成人工接管期间的命令。保留控制权区间、交接事件，以及影响解释数据的策略/映射版本。核查是否必须切分 episode 或扩展标注；自动/混合模式需同步扩展当前 control_mode 校验、Manifest 和输出元数据，不标成主从臂数据以绕过限制。

## 时间与质量验证

- 核实相机曝光/采样、输入生成、命令发出、控制器接收和观测时间戳中实际可获得的字段，记录单位、时钟关系及不可测的延迟。
- 明确 observation(t) 与 action 的对应区间；对齐过程不得未经说明使用未来观测生成动作。
- 对绝对目标、增量、速度和离散事件分别验证重采样含义。尤其检查重复采样是否会重复应用增量，以及是否丢失按钮边沿或切换事件。
- state/action 分别定义维度、名称、单位和语义检查项。数据转换不执行关节/动作软限位、URDF 位置/速度限位或其他机器人运动约束门禁；这些约束属于控制器、规划器和安全层。不得因数值超出标称范围而裁剪、删除或阻断 episode。
- 用能发现错误的样本验证：已知坐标变换、左右交换、错误单位/姿态顺序、失效跟踪、时钟偏移、缺命令、重置/控制权切换。保留有效样本和应拒绝/标记的样本。机器人限位不用于数据集转换准入。
- 核查固定 letools 与 Doctor 对新特征的实际支持、检查覆盖与预览行为。结构验证通过不能替代动作语义验证。
