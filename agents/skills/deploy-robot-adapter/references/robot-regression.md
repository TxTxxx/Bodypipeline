# 现网回归矩阵

部署新机器人后，现有机器人必须逐项证明没有被改变。以下矩阵适用于 Server 变更；Client-only 部署可以缩小范围，但仍要验证新 Client 不会被旧 Server 误接受。

## 1. 识别机队

从部署配置中生成机器人清单：

```text
robot_id | robot_type | project_id | Client 地址 | Server 实例 | Profile
```

要求：

- 每台机器人的 Client `server_url` 指向明确实例；
- 每台机器人有独立设备凭据；
- 机器人类型和 Profile 可以追溯；
- 没有机器人同时指向两个活动实例；
- 没有两个实例共享可写状态根。

## 2. 基线快照

部署前保存只读快照：

```text
服务健康
上传记录数量
collection 数量
任务状态计数
RUNNING / QUEUED 任务
最近一个可预览任务
Viewer 活动状态
data_root 可用空间
```

只记录摘要和状态，不复制密钥，不修改任务。

## 3. 回归矩阵

| 项目 | 新机器人 | 每个现有机器人 | 通过标准 |
| --- | --- | --- | --- |
| Client 健康 | 必须 | 必须 | `/healthz` 和 `/api/health` 正常 |
| Bridge | 如适用 | 如适用 | service、topic 新鲜度和 owner 正常 |
| 设备认证 | 必须 | 必须 | 正确设备成功，错误设备 401/403 |
| 目标授权 | 必须 | 必须 | 只能使用允许的 target |
| 上传 | 必须 | 至少 1 条 fixture | offset、摘要和 commit 正常 |
| collection | 必须 | 必须 | 不与其他 robot/profile/format 混组 |
| 旧状态读取 | 必须 | 必须 | 旧上传和任务可列出且状态不变 |
| 转换路由 | 必须 | 必须 | 进入各自 Runtime / Provider / Profile |
| 错误路由 | 必须 | 必须 | 未知类型/格式被拒绝 |
| Doctor | 必须 | 最近样本可运行 | 11 项非运动学检查正常 |
| Viewer | 必须 | 至少一个最近结果 | 会话、视频 Range、过期行为正常 |
| 数据目录 | 必须 | 必须 | 没有跨 `robot_type` / 实例读写 |
| 服务隔离 | 必须 | 必须 | 重启新实例或目标 release 不影响旧实例 |

## 4. 负样本

至少验证：

- 使用机器人 A 的凭据上传机器人 B 的 Manifest：拒绝；
- 未注册 `robot_type`：拒绝或明确 BLOCKED；
- 未知 `raw_format`：拒绝；
- 错误 Profile 摘要：拒绝或明确阻断；
- 跨项目 target：拒绝；
- 导入路径不在 `import_roots` / `data_root`：拒绝；
- Viewer 无活动会话：503，而不是打开其他机器人数据集；
- 新实例的端口、root、data_root 与旧实例冲突：启动前失败。

## 5. 观察窗口

部署后至少观察：

- 现场一个完整采集上传周期；
- 旧实例一次管理页刷新和任务列表读取；
- 队列没有自动重跑；
- systemd 重启次数和错误日志；
- 磁盘水位没有异常增长；
- Viewer 会话归属正确。

真实机械臂运动、真实遥操作和停止排空只在用户明确授权时执行；没有授权时用静态采集或 fixture，并明确标记未做真机运动验收。

## 6. 通过条件

所有现有机器人完成最低回归，且没有跨机器人状态、路由或数据目录变化，才能结束部署。

如果只能验证新机器人，应把部署标记为“隔离实例已上线，旧机队回归未完成”，不能宣称共享 Server 发布通过。
